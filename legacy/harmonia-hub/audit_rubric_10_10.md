# Rúbrica de Auditoría Máxima (Estándar 10/10)

Para que cualquier producto o repositorio sea considerado apto y se publique en GitHub, debe superar de forma objetiva y demostrable (con código, pruebas automatizadas y contratos tipados) cada una de las seis dimensiones siguientes:

1. **Backend (10/10):** Arquitectura robusta, tRPC/REST con tipado end-to-end, migraciones Drizzle sincronizadas, autenticación segura con cookies HttpOnly/Secure/SameSite y manejo de errores con fallbacks estructurados.
2. **Frontend (10/10):** Interfaz sofisticada, glassmorphism con desenfoque real (`backdrop-filter: blur(16px)`), paleta minimalista coherente, microinteracciones fluidas (<300ms) y diseño responsivo adaptado a móvil/web.
3. **Utilidad (10/10):** Resolución de un problema real, de alta frecuencia para desarrolladores o creadores, con un flujo sin fricción y coste operativo de infraestructura menor a 12 € anuales.
4. **Relevancia (10/10):** Alineación perfecta con las demandas actuales del mercado tecnológico (privacidad local-first, encriptación, automatización sin dependencias pesadas y portabilidad).
5. **Potencial (10/10):** Modelo de negocio claro (freemium / SaaS / open source con valor comercial), escalabilidad horizontal y arquitectura preparada para integraciones futuras.
6. **Identidad (10/10):** Coherencia de marca inquebrantable, nombre único, diseño visual inconfundible y documentación técnica rigurosa.

*Regla de exclusión:* Si alguna dimensión obtiene menos de 10/10, el producto no se publica en GitHub y se documentan los puntos de fricción para su corrección estricta.
